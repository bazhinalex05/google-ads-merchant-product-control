# Google Ads Merchant Product Control

Google Ads Script для керування товарами інтернет-магазину: читає Merchant Center і статистику Google Ads, визначає етапи воронки, застосовує категорії, сезонність та карантини і формує додатковий фід Products.

## Код і документація

- [script.js](script.js) — актуальний код для Google Ads Scripts.
- [Інструкція: налаштування й читання таблиці](docs/user-guide.md) — почніть тут. Усі листи й налаштування звичайними словами, з прикладами.
- [Фактична технічна логіка листів](docs/technical-reference.md) — докладні правила, джерела даних, умови, періоди, колонки та обмеження.
- [Історія змін](CHANGELOG.md) — перелік змін у випусках.

Інструкція й технічний довідник доповнюють одне одного. Передавайте обидва документи разом зі скриптом. Для запитання до ШІ додайте назву листа, поле й приклад результату.

## Початок роботи

1. Створіть Google Sheets таблицю для проєкту.
2. Створіть Google Ads Script у потрібному рекламному акаунті та вставте весь вміст script.js.
3. Замініть значення SPREADSHEET_URL у верхній частині коду посиланням на свою таблицю.
4. Увімкніть Advanced APIs Merchant API Products та Accounts і надайте скрипту необхідні дозволи.
5. Запустіть скрипт для створення Settings. Заповніть Merchant ID та інші параметри за [інструкцією](docs/user-guide.md).
6. Повторно запустіть скрипт, перевірте журнал виконання й результат у таблиці. Після перевірки налаштуйте регулярний запуск.

## Перевірки й обмеження

Локальні перевірки:

```text
node tests/sheet-regressions.cjs
node tests/quarantine-lifecycle.cjs
node tests/funnel-catalog-scope.cjs
node tests/quarantine-counter.cjs
node tests/category-label-independence.cjs
node tests/target-cpa-fallback.cjs
node tests/quarantine-registry-reasons.cjs
node tests/dashboard-extended-layout.cjs
node tests/quarantine-reset.cjs
```

Вони не замінюють запуск у Google Ads. Dashboard і DashboardData містять чотири причини карантину та витрати активних товарів за спільний період воронки. Службова галочка reset_quarantine очищає тестову історію й не дозволяє призначати паузи, поки її не знято вручну. Перевірка природного виходу та повторного входу на бойовому проєкті потребує багатоденного спостереження.

Не додавайте до публічного репозиторію клієнтські посилання, ідентифікатори акаунтів або секрети. Індивідуальні параметри зберігайте у власній копії скрипта та таблиці.
