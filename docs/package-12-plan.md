# Пакет issue #1: попереднє рев'ю та план

База: `46deed7`, v1.2.1. Робоча гілка: `feature/unified-12-improvements`.
Дозвіл на реалізацію всього пакета отримано 19.11.2026; історичні заборони негайних змін у списку ідей замінені цим дорученням. Main і клієнтські системи не змінюються.

| № | Поточний стан | Ціль і модулі | Сумісність та перевірка |
|---|---|---|---|
| 1 | Priorities → категорія → Merchant → other | `product_types_sheet`: тільки priority категорії, найглибше непорожнє правило | Порожня категорія успадковує батька; без правила порожньо. Priorities і Merchant ігноруються. Перевірити конфлікт джерел. |
| 2 | Немає вимкнення джерел | `none` у reader і resolver | Не читати Priorities або Merchant priority; ручні значення ProductTypes зберігаються як дані редагованого звіту, але не використовуються. |
| 3 | Обов'язкова custom label; вимкнений writer очищає заголовок | `none` у output; не писати п'яту колонку | Стару колонку не видаляти й не очищати автоматично. Наявна колонка потребує окремого рішення до публікації; не переставляти ID під старими значеннями. |
| 4 | Є conversions та cost 30d, немає clicks/CR | Додати clicks_30d і cr_30d, сума conversions / сума clicks | Той самий 30-денний період включно сьогодні, та сама перша категорія товару й предки. Нуль кліків → порожньо. Перевірити дробові конверсії та батьківські категорії. |
| 5 | Уже є enable_sheet_protection; Seasonality безумовно знімає захист | Використати чинний перемикач; не чіпати чужий захист | false залишає захист без змін. Перевірити canEdit та помилки створення; не називати відмову запису помилкою авторизації Ads. |
| 6 | A, B, ceil((A+B)/2), guard різноманітності | Документувати без зміни функцій порогів | Приклади 0%, 25%, 30% нулів; перевірити межі >A та >=T. |
| 7 | Є тільки назви категорій, URL не надані Merchant product_type | Ручне підтверджене category_url за path_key; RichText назви категорії | Не виводити URL з назви/URL товару. Без підтвердженого URL залишати текст і повідомляти кількість пропусків. Повне покриття залежить від заповнення URL. |
| 8 | enable_products_write зберігає старий фід | Окремий enable_products_output: false очищає вміст Products | Має вищий пріоритет за технічний write-switch, включно dashboard-only. Розрахунки не вимикаються. |
| 9 | Карантин додає excluded_destination | Причина у вихідному Funnel Stage; category/season exclusions залишаються | ID без змін, вихід відновлює поточний етап; перевірити карантин із вимкненою воронкою. Кампанії перевіряє користувач до застосування фіда. |
| 10 | Diagnostics — стан; Registry та Log — історія з правилами збереження | Аналіз коду та відтворювані локальні сценарії | Без клієнтських ID неможливо підтвердити конкретний дефект; окремо описати очікувані розбіжності й протокол збору доказів. |
| 11 | ProductTypes явно розкриває колонки | Прибрати примусове розкриття; зберегти видимість за заголовками при зміні схеми | Перевірити повторний запуск, нові колонки та інші звіти. |
| 12 | Settings.clear + повний rewrite при кожному читанні | Додавати відсутні ключі на місці; оновлювати лише потрібні validation | Не міняти ID/назву/рядки існуючих ключів, значення/формули/невідомі ключі/named ranges/protections. Повтор після збою перечитує ключі й додає лише відсутні. |

Порядок: Settings migration → priority / Products switches → CR / URL / видимість → карантин / захист → документація → регресії → commit і push гілки → один цикл тестування користувачем.

Відкриті залежності: підтверджені URL категорій; дозвіл на прибирання старої priority-колонки, якщо обрано none; конкретні ID/дати для п.10. Незалежні частини реалізуються без очікування.
